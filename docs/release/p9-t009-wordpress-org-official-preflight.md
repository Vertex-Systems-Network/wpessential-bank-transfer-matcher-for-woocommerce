# P9-T009 — Real WordPress.org Plugin Check and online readme validator preparation

**Engineering implementation draft — no public submission, SVN commit, or guaranteed passing validator.** Source official docs: <https://wordpress.org/plugins/plugin-check/>, <https://github.com/WordPress/plugin-check/blob/trunk/docs/CLI.md>, <https://wordpress.org/plugins/developers/readme-validator/>, <https://developer.wordpress.org/plugins/wordpress-org/how-to-use-subversion/>.

The dedicated Actions workflow `.github/workflows/p9-wporg-official-preflight.yml` creates a brand-new disposable WordPress **7.0.8**, WooCommerce **11.3.0**, PHP **8.3**, MariaDB **11.4** site and installs the **actual WordPress.org Plugin Check** release in that site. It separately builds the real Free ZIP with optimized Composer production autoloader. It runs `wp plugin check wpessential-bank-transfer-matcher --mode=new --format=json` without selectively ignoring check codes. Raw official JSON, stderr, actual scanner version and command exit status are always retained in an artifact. Any findings must be reviewed; command execution is not automatic "PASS".

The job also POSTs **only the generated public Free readme.txt content** to the public official readme validator page. A strict parser recognizes the actual `notice-success` / `Congratulations! No errors found.` server response only after HTTP 200; otherwise it reports fatal errors or **UNVERIFIED**. HTTP 200 by itself never proves validation, and no credential or submission occurs.

`scripts/p9-wporg-official-preflight.py --svn-dry-run` builds `dist/p9-wporg-svn-dry-run/trunk` and `tags/<version>` from real packaged Free ZIP bytes. It validates no Pro source, correct readme and identical trunk/tag files; `assets` is empty because verified WordPress.org listing assets/icons have **not** been provided. No attempt is made to contact/commit to the public SVN repository.

The full real outputs are uploaded as `p9-wordpress-org-real-plugin-check-and-readme`. Task acceptance requires inspecting that artifact, authentic scan results (including every finding), readme validation outcome (which may remain unverified), actual WP.org plugin submitter/2FA/approved slug/SVN committer rights still external, and final release safety gates. Do not report official online validator success if the network/form response is unrecognized. No production merchant/bank/customer data or public release.
