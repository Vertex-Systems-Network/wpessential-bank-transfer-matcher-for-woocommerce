# P7-T002 — native WordPress/WooCommerce Free + Pro layout implementation

Status: implemented on draft P7 PR #13; latest full source-head CI and browser visual checks must be independently confirmed. This is **real WordPress PHP render output and scoped CSS**, not a Figma mockup or claim that all 14 screens passed visual QA.

## Screen ownership and design strategy

The UI remains in WordPress wp-admin under existing WooCommerce submenu registrations. No invented REST routes, report Saved Views, bank authorization toggles, global audit explorer or decorative controls have been introduced. Every changed action still executes its existing WP admin GET filter or nonce-gated POST/REST handler.

- Free CSS `plugins/wpessential-bank-transfer-matcher/assets/admin.css` is scoped to `.wbm-admin` and the already rendered order panel. The Free order list `Admin/OrdersPage.php` retains real WooCommerce CRUD/HPOS queries and existing status/20-item pagination. It now exposes a keyboard-focusable, named table region and wraps its real filter and page controls on narrow displays.
- Pro CSS `plugins/wpessential-bank-transfer-matcher-pro/assets/admin.css` is loaded via the new `Admin/NativeAdminAssets.php` **only** for the eleven registered `woocommerce_page_wpessential-wbm-pro-...` submenu hooks. `Bootstrap/Plugin.php` registers this enqueue callback. It is explicitly **not** loaded on the independent Free menu, order editor, product editor, storefront or arbitrary admin pages. Its selectors are additionally restricted to the Pro WooCommerce page body class.
- The font hierarchy, white surfaces, subdued WordPress gray boundaries, system interaction accent and native `wp-list-table`, `form-table`, `postbox`, `button`, `notice` markup stay native to the current WP/WC install. No external font, React replacement or SaaS dashboard is added.
- Pro UI-009 review queue: `Admin/ReviewQueuePage.php` has visible `Case state`, `Priority`, `Assignee user ID` and `Rows per page` labels, actual GET search region, real case table inside named keyboard-focusable scroll region and a named previous/next navigation element. Its three-column case detail now uses external CSS rather than its former inline `<style>`, collapsing to one column below 1100px. Actual review REST operations and permissions were **not** changed.
- Pro UI-011 finance dashboard: `Admin/FinanceDashboardPage.php` uses external native form-panel/card classes, real per-currency/per-state page-only KPIs and an accessible horizontal-scroll region for focused source details. All existing filters, data scope, cursor and read-only constraints remain.
- Pro UI-008 imported statement rows: `Admin/BankTransactionsPage.php` uses a genuine GET filter toolbar, labelled page-size control, named horizontally scrollable source table and previous/next navigation. Imported evidence is still unverified, masked and does not pay orders.
- Pro UI-007 imports: `Admin/ImportStatementsPage.php` wraps the real CSV import preview and import history tables, preserving the server-side two-step preview/commit, checksum, private jobs and existing nonce actions.
- Pro UI-010 allocation ledger: `Admin/AllocationReviewPage.php` labels the bounded page-size control, exposes actual filters as a search region, and wraps the 11-column ledger, correction/reversal case, correction history and append-only allocation event tables separately. Its existing manual proposal and independently checked approval dialogs, hold protections and financial proof flows are untouched.
- Pro UI-014 operations: `Admin/FinanceOperationsPage.php` uses a keyboard-scrollable source-specific history for import/export/digest jobs; its redacted export and manual recovery retain original capability/nonce/rate guards. Bank accounts also wrap the native masked metadata table.
- Pro UI-013 mapping profiles: `Admin/MappingProfilesPage.php` adds *distinct accessible names to all 13 actually implemented* CSV mapping inputs/selects, including the separate date header/date format, decimal/thousands, currency header/fixed ISO currency, reference/description and bank transaction ID fields. The saved-profile table is keyboard-scrollable. The actual mapping validation and storage remain unchanged.
- Other Pro forms (`ReportExportsPage`, `FinanceNotificationsPage`, `FinanceRetentionPage`) continue using real native `form-table`/form controls, buttons and server-side actions; the shared Pro stylesheet applies consistent text fields, focus rings, max widths and mobile form flow without changing these handlers.

## Accessibility and responsive choices

Table scroll wrappers are `role=region` with a grounded accessible name and `tabindex=0`, to preserve every financial column at 375px instead of hiding or folding away balances, state and audit. GET forms retain native labels and WP button presentation. RTL uses logical CSS properties (`inline-size`, `margin-inline`, `padding-block`, `border-inline-start`) where new properties are introduced; no English-only mirrored screen mockups are claimed. Keyboard focus uses visible native WP accent outlines, plus forced-colors outlines and border fallback. WP-native mobile breakpoint is 782px, with detail grid collapse at 1100px. No artificially animated skeleton or fake async spinner is shipped.
